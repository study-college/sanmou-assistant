# 0.9.9 — 拉线闭环与现场识别修复

> 对应源码版本 `0.9.9`，Windows 完整包由标签在 GitHub Actions 上独立构建。
> 原创代码 MIT；第三方组件权利见包内 `THIRD_PARTY_NOTICES.md`。

## 版本重点

0.9.9 把「拉线」从“能读能派”推进到“按你的指令持续拉”的闭环，并修复了实机暴露的几类识别/稳定性问题。

### 1. 拉线按目标配置的指令顺序执行

- 拉线目标与武勋目标同构：在「目标与铺路 → 拉线目标」里点“指令顺序”，自由排列 **攻城 / 攻占 / 驻守 / 行军**。
- 脚本按这个顺序尝试；目标菜单没有的指令自动换下一个，不再写死“攻占/行军”。

### 2. 忙碌到出击线就补兵继续拉

- 金色时钟（忙碌）在游戏里可能是**自然征兵**或**占领**。脚本会在出征页按卡片文字区分：
  - 卡片是「征兵」→ 点「一键补兵」，补完继续按配置出征；
  - 卡片是「占领 / 战斗 / 重伤 / 撤退 / 行军 / 驻守」→ 放弃本次，稍后重试。
- 指令里没有「攻占」时，占领不可能是这条拉线指令的结果，忙碌按征兵处理，减少无意义的核对与等待。
- 每轮每队最多点一次「出征」；没受理就下一轮重读，不在同一页连点。

### 3. 补兵、回城与补兵点闭环

- 一键补兵后仍低于出击线：**不带着残兵出征**，改为回城；回城/撤退需要几分钟，脚本会等现场后继续。
- 队伍在主城（包括自然征兵中）且配置了补兵点时，**先调动到补兵点再拉线**；补兵点可以是营帐、城池等，按「部队任务 → 详情」里的顺序选择。
- 到补兵点后：兵力够出击线就从那里拉；不够就在补兵点继续自然征兵，到线再拉。
- 有任务的队伍，调动页「自动征兵」关闭时脚本会勾选并复读确认。

### 4. 现场识别修复

- **右侧队伍列逐行偏移**：选中建筑/地块后，站在该地块上的队伍头像会左移约 25px。脚本改为每个槽位在已测布局里各自匹配，不再假定整列固定；建筑内“忙碌/调动停留”不再被读成未知。
- **撤退卡片**：出征页卡片只写「撤退 mm:ss」时也能识别，不再把撤退队继续提交。
- **重伤与角标同帧**：读取角标的那一帧同时判断重伤，避免两帧结论打架。
- **未知页面恢复**：攻城/战斗全屏特效把建筑详情留在屏幕上导致页面暂未识别时，先左右滑动地图取消选中再重判，不再干等特效结束。
- **隐藏显示**：启动时没读清小眼睛会下一轮重试，不再一次跳过；进出主城后仍会重核。

### 5. 稳定性修复

- 修复拉线两帧复核里 `Worker` 不存在 `self.d` 导致的崩溃。
- 修复点完「一键补兵」后调用 `Game.publish` 不存在导致的崩溃；补兵回执事件改为正常发出。
- 日志不再重复打印坐标；队伍名不再累积「（未拥有）」；没有启用拉线目标时明确提示而不是静默跳过。

## 升级与使用

- 升级前停止助手并备份自己的 `data/`；不要用空白数据覆盖已有配置。
- 完整包解压后运行 `启动助手.cmd`，首次启动会创建自己的 `data/`。
- 拉线队伍在「部队任务」里选“拉线”，在「目标与铺路 → 拉线目标」配置坐标与指令顺序，在队伍“详情”里配置补兵点顺序与“补不动时”的兜底。

## 边界

- 其他账号、赛季布局与长期无人值守仍需分别验证。
- 目标必须是当前菜单里真实可用的地块/建筑；目标被拆除后只剩「行军」，脚本会按配置顺序退到可用指令。
- 识别与模拟输入都可能出错；脚本在无法确认时选择等待，不盲点。
