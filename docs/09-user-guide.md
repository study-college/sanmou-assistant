# 三谋助手 0.9.5 使用指南

本包同时提供可直接运行的程序和同版本源码。普通使用不需要 AI 或 Python；需要 AI 帮忙时，程序旁也有完整操作手册。

## 多账号控制

窗口顶部“控制账号”用于切换账号，“添加账号”用于绑定另一个 MuMu 实例。每个账号都有独立的设置、Worker、运行日志、截图、订单和日常记录；界面仍使用下面的八个页面和相同操作逻辑。

- 切换账号只切换当前页面，不会停止或接管其他账号的后台任务。
- “开始执行 / 停止任务 / 只监控 / 保存设置”只作用于当前账号。
- 添加账号时可以复制当前策略作为模板，但账号与主城会清空，必须在新实例里重新校验。
- 不同账号可以分别绑定不同实例并独立运行；同一实例不能同时被两个账号任务占用。
- 关闭整个软件时会逐一停止所有账号的新输入，不撤军、不取消游戏内任务。

首次从旧版升级时，原 `active-profile.json` 和历史数据保留，原配置会迁移为第一个账号。新数据位于 `data/accounts/<账号ID>/`，其中 `profile.json` 是设置，`sessions/` 保存会话、截图和独立 SQLite。

## 解压与首次配置

1. **先完整解压**，例如放到 `C:\Games\SanmouAssistant`。保持文件夹完整，不要只拿走 exe，也不要在压缩包预览里运行。
2. 双击根目录 **启动助手.cmd**。也可以打开 `app/SanmouAssistant.exe`，两个入口使用同一份数据。
3. 打开自己的 MuMu，启动装有游戏的实例，并由本人完成游戏登录。
4. 在助手的“连接与配置”点击 **自动发现实例**。找不到时，从 MuMu 快捷方式“打开文件所在位置”，找到安装目录里的 `nx_main/mumu-cli.exe`，选择它后再发现。
5. 按名称选择自己的实例。下拉框里的 **编号 N 就是实例 ID**，不是 ADB 端口，也不是列表的第几行。多开时通过“刷新画面与资源”的预览再次核对角色。
6. 点击 **发现游戏包名**。单个渠道自动填入；多个候选时，选择自己登录的渠道。没有候选可手动填写，不照抄别人的包名。
7. 回到沙盘，点击 **校验账号与主城**。助手定位本人主城，核对昵称和主城坐标，不要求第1队在城内。
8. 设置队伍、战场或铺路路线，保存后先点 **只监控**。确认读数属于自己，再点 **开始执行**。

> 换电脑、账号或区服后，重新发现实例并校验主城。新包没有作者的账号配置、数据库或游戏截图。

## Windows 与 MuMu

| 项目 | 要求与验证范围 |
|---|---|
| 电脑 | Windows 10 1809及以上 / Windows 11，Intel或AMD x64。Windows 7/8、ARM、macOS、Linux不在本版支持范围 |
| 模拟器 | Windows MuMu 5，包含 `nx_main/mumu-cli.exe` 和可用的ADB；本机实测基准为 **5.30.1.3586** |
| 游戏界面 | 简体中文，推荐实际 **1920×1080 横屏**。其他16:9尺寸按比例处理，其他比例拒绝操作 |
| 桌面缩放 | 窗口按可用逻辑尺寸打开；小屏幕时设置页可滚动、表格可横向滚动，不必修改Windows全局缩放 |
| 程序版 | 不需要安装Python或CUDA；OCR模型和主要运行依赖已随程序打包 |
| 源码版 | Python **3.11–3.12 x64**；第一次安装依赖需要网络 |

从 [MuMu官网](https://mumu.163.com/) 获取模拟器。本包不包含模拟器、游戏或账号。雷电、蓝叠、MuMu Mac和旧MuMuManager接口尚不支持。
系统下限参考 [Qt支持平台](https://doc.qt.io/qt-6.10/supported-platforms.html)，运行库要求见 [ONNX Runtime安装说明](https://onnxruntime.ai/docs/install/)。

**赛季前期暂未验收。** 当前分页和兵力识别基于后期布局及三将阵容，不能保证只有1–4支已解锁队伍、未满三将时兼容。没有要求所有8队都开启任务，但请不要把这一点当作前期布局已支持；后续将根据真实前期样本迭代。

## 文件与启动入口

| 文件或目录 | 什么时候用 |
|---|---|
| `启动助手.cmd` | 普通使用入口，无需AI或Python |
| `先读我.html` | 当前这份离线说明，表格、目录、图片都可直接阅读 |
| `app/` | 程序及其运行依赖，保持完整 |
| `安装源码环境.cmd` | 有Python、准备运行或修改源码时，先用它安装隔离环境 |
| `启动源码.cmd` | 源码环境安装完成后使用；与程序版共用根目录data |
| `source/` | 完整产品源码、识别资源、公开回归测试及构建脚本 |
| `docs/AGENT-GUIDE.html` | 适合直接阅读的Agent操作手册；同目录也有Markdown原稿 |
| `导出诊断.cmd` | 不打开游戏，导出已有诊断记录到根目录feedback.zip |
| `校验完整性.ps1` | 按文件大小和SHA256检查原始发布文件 |
| `data/` | 首次运行后创建，保存本人的配置、日志和持久记录 |

程序版和源码版可以任选，但不要同时控制同一个实例。源码安装器会自动查找支持的Python版本，也可由Agent明确指定Python路径。

## 先监控，再执行

- **只监控**：连接并导航读取，不派兵、不撤军、不领取奖励。
- **开始执行**：立即按你保存的开关执行武勋、铺路或日常任务。
- **停止任务 / 关闭窗口**：停止新输入，等当前工作线程退出并释放实例控制权；不会撤军、取消游戏内行军或关闭模拟器。

已发送给游戏的操作不会因停止而撤销。正在OCR计算时，会在本次计算返回后响应停止；CLI和ADB等待支持中断。
模拟器可以保持最小化，截图与输入都走Android，不需要游戏窗口一直在前台。

## 队伍与战场

在“部队任务”给每支队伍选一个任务：**刷武勋**、**讨贼**或**铺路**，只选一个；暂时不用的队伍可以在运行总览里取消勾选隐藏，隐藏的队伍完全不参与执行。启动时会从游戏部队详情/总览左侧的“部队一/二/…”读取本次实际有哪几队；有几队就用几队，未拥有的槽位保留配置但不读取、不派兵，并在设置页锁住不能修改，也不需要分页条或亲卫队。每支队伍在自己的行里点“详情”，配置目标组与补兵点顺序；选“铺路”时再挑一条已建好的路线。规则与限制收在每页的“▸ 说明”里，页面只保留一句目的和现场状态。没有安排任务的队伍不会自动出征；亲卫自动出征暂未开放。每批队伍首次读取时会在左侧逐队切换并连续读取，最后统一关闭，不再为每队重复进出详情页；地图位置和实际选中槽位仍会分别核对。

战场支持粘贴游戏分享地址，可连续粘贴多个。新地点默认关闭；同坐标保留已有设置。名称是备注，实际定位必须匹配坐标。
选中地点后用上移、下移、置顶、置底调整顺序；指令也按你允许的顺序尝试。

主城空闲或城外停留的队伍，实际兵力达到本队下限、伤情与体力补给达标后可以出击。主城不用强制全队满兵；城外备用补兵仍按原策略真实征满后回城。正在行军、回城、驻守、征兵或执行铺路的队伍保留当前任务。

运行总览的“实时日志”按产生顺序显示最新进度，默认跟随最新，可手动“清空显示”。重新启动任务会清空旧任务的界面日志；磁盘会话记录保留，仍可导出诊断。

粮食是所有队伍共用的账号库存。短暂遮挡不会清空最近读数；成功读数最多使用120秒，过期后等待重读。真实读到低库存时立即暂停新出征；“库存未读到”不表示缺粮，也不会凭此消耗屯田次数。

## 讨贼次数

在“补兵与日常”开启讨贼，并在“部队任务”把要参加的队伍任务选为**讨贼**。默认只参加有奖励次数的讨贼，以游戏页面实际余数为准，不按本地启动次数推算。余数归零后，本周期停止新讨贼及反复打开列表；已经出发的队伍继续监控，游戏7时刷新后重新读取。

有有效奖励次数和可集结部队时，沙盘固定号角是讨贼快捷入口，助手识别后直接点击；未识别到号角时仍可通过城务进入。加入后列表可显示“已参加”且没有加号，助手不会重复加入；目标从列表消失不再单独视为成功。

需要额外参加时，可单独开启“奖励次数用完后继续协助讨贼（无次数奖励）”。默认关闭，开启后仍只使用已勾选的讨贼队伍，不自动新建集结。次数未识别或加入结果不明时不重复提交。
**武勋的自然补兵策略保持不变**，不会因为新增铺路选项而替你开启快速补兵。

## 铺路：看队伍状态，不猜时间

在“铺路路线”添加路线，选择一支主城队伍，点“编辑路线”，粘贴按顺序排列的游戏地址或坐标。每队同时一条启用路线，段数不设上限（2026-11-10 起取消原来的 30 段限制），几十上百段都会被原样保存并逐段推进。

行军、占领或自动铺路还在进行时，助手继续观察；**不按白天三分钟或夜间十几分钟设死完成时间**。伤情倒计时也是参考，归零后仍重新读取游戏。

0.9.0 沿用简化后的多阶段铺路：到达目标点并读到“停留”角标后保存进度，再继续下一点；行军、忙碌、战斗或撤退时等待现场恢复。不用地图颜色推测完成，也不以历史归属代替队伍状态。

0.9.3 起：攻占空地的守军战斗是铺路正常过程，助手只等待战斗结束再衔接，不当作异常；如果战斗后队伍重伤，才需要人工或后续版本处理。目标点已经被别人铺到、地块菜单没有“攻占”时，助手跳过该点继续下一个点。出征时如果出现“补给不足”提醒，助手会勾选“今日登录不再提示”并点“确定”后继续；这条只处理补给提醒，不会改点其他弹窗。坐标定位不再回读输入框，点“前往”后以实际到达的地块坐标为准，输错或没生效会自动重输一次，仍不对就停下，不会盲点攻占。

0.9.4 起：运行总览会显示“本次铺路 ?/?”，铺路队伍那一行常驻显示“铺路 12/17 · 下一点 (x,y)”，完成后显示“铺路完成 17/17”；详细过程仍在日志里。巡检遇到暂未识别页面时会先尝试关闭已识别的月卡/活动/聊天/渠道等弹层再重读，跨天出现的月卡领取标志或弹层不会卡住铺路；助手只关闭，不自动领取月卡、不进入购买入口、不改日常开关。

0.9.5 起：铺路路线不再限制 30 段，原先输入 100 多段会被“需要 1～30 个坐标”拦住而无法保存；现在长路线可直接保存，已有路线不做迁移。编辑器的粘贴框同步放大，避免长路线在粘贴阶段被截断。

下一段可从已经确认停留的位置继续，不要求一直站在上一段终点。未完成路线优先保留给对应队伍；没有自动换队接力。更换路线队伍或坐标会产生新的路线版本。

0.7.4 起已移除“被击退或重伤回城后继续”和路线补兵选项，不再自动办理营帐征兵、辎重补兵或取消征兵。实战补给下降不影响出征；遇敌路线重选和击退恢复仍未实现，不能依赖该版本自动处理这些情况。

## 军演与同盟宝箱

在“补兵与日常”开启 **军演挂机奖励**、**同盟奖励宝箱**。开始执行后，助手查看主页面“征战”或“同盟”图标右上角的黄色宝箱：

![征战图标右上角的黄色奖励宝箱](guide-assets/reward-chest-location.png)

**出现才领取，没有就继续其他任务。** 军演挂机奖励可以在同一天多次出现，不再因为“今天已领过”而整天跳过；也不靠零点或7时猜测宝箱已经刷新。
领取前核对账号并记录，领取后看奖励弹层或宝箱消失证据。中断或结果不明确时先重新读取，不无上限地重复点击。

这两个开关只领取已有免费奖励，不自动挑战军演关卡、不购买礼包。只监控不会领奖。
月卡、签到、活动、寻访等仍有各自开关；半价寻访必须明确开启才会消耗游戏黄金。职业技能暂不自动执行。

## 反馈问题与诊断

1. 记下大致时间、正在做的任务、所选实例和预期结果。
2. 到“日志与诊断”点击 **导出问题诊断包**，也可双击根目录“导出诊断.cmd”。
3. 解压反馈ZIP，打开其中的 **请先打开诊断报告.html**；核对内容后把整个ZIP交给维护者。

任务记录包含版本、运行过程、错误堆栈和本地摘要。反馈包最多包含最近三个会话、每个文字文件2MiB尾部、每张业务表最近100条，以及最多12张截图、总计16MiB。
它不包含完整数据库或登录凭据，也不会自动上传；但截图和配置可能带游戏昵称、坐标与本机路径，发送前请核对。

误入活动等页面时，若识别到游戏返回箭头和页面标题，会有限尝试返回沙盘，并重新读取队伍后继续。单次最多返回2步，10分钟最多3步；暂时无法确认画面或返回控件时暂停本轮输入，按巡检间隔重读。异地登录、服务器维护和持续设备故障仍停止任务。**服务器维护不会自动反复登录**，维护结束后再手动开始。
如果程序窗口尚未打开就退出，保留 `data/crash.log`；若连Python运行时都没加载，则提供系统提示截图和完整性校验结果。

新截图按普通/动作/故障128/128/32MiB、最长7天滚动保存；订单记录独立保留。不要删除数据库来解除未知订单或腾截图空间。

## 常见问题

| 看到的问题 | 先这样处理 |
|---|---|
| 找不到MuMu | 选择真实安装目录内nx_main/mumu-cli.exe，再发现实例；错误路径不会悄悄切换到另一安装 |
| 实例不存在或预览不是本人 | 重新发现并按名称、编号选择，用昵称和主城确认；不要把端口当作实例ID |
| 提示没有安装所选游戏包 | 启动正确实例，使用“发现游戏包名”重新匹配渠道 |
| 提示另一任务正在控制实例 | 正常停止并关闭另一个助手，等退出后再接管；AI也不要同时直接操作ADB |
| ADB未就绪 | 等MuMu进入安卓桌面后重试，不需要重启全局ADB服务 |
| 页面或队伍读不到 | 核对横屏1920×1080、简体中文与当前游戏状态；保留诊断，不放宽保护来盲点 |
| 提示DLL缺失 | 校验文件并完整重新解压，勿只复制exe；仍失败时按微软官方渠道补齐VC++ x64运行库并反馈 |
| 无法保存或导出 | 使用本人可写目录，避免Program Files、只读介质和仍在压缩包内运行 |
| 铺路一直等待 | 看队伍是否仍在行军/占领、是否重伤、是否有未确认记录。夜间较慢本身不会触发超时 |
| 没有看到同盟宝箱 | 以游戏实际出现为准；没有宝箱时助手不会盲点或反复进入同盟 |

## 升级、备份与完整性

升级前停止任务并退出助手，备份自己的data。把新程序解压到独立目录，再明确迁移自己的配置和持久记录，不要用空白data覆盖旧数据。
新电脑使用自己的账号配置；保留旧版成品便于回退，回退时也使用对应版本的备份配置。

完整性检查：在解压根目录运行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\校验完整性.ps1`。
用户新增的data、反馈包和源码虚拟环境不属于原始发布文件，不影响原始文件逐项核验。修改了源码后，相关哈希自然会变化。

## 交给 Agent 使用

可以让AI先读 [Agent操作手册](AGENT-GUIDE.md) 和 `source/AGENTS.md`。说明书列明了命令、实例互斥、账号校验、日志和重建方式。
源码环境首次安装使用锁定依赖；普通用户直接使用程序即可。其他真实电脑、账号、渠道、赛季布局和长期稳定性仍需分别验收，不能用单台电脑的测试替代。

源码安装器优先选择标准CPython，不自动选择Anaconda/Conda。后者的Qt/DLL环境不在源码适配范围；只有Conda时可使用无需Python的程序版，或另装python.org的标准CPython。安装后会检查Qt/OCR能否加载。已有.venv若属于另一解释器，应先移出备份再重新安装，不能混用。
