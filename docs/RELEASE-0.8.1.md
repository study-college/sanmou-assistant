# SanmouAssistant 0.8.1

Windows 10/11 x64 · MuMu 5.30.1.3586 基线

## 这一版做了什么

0.8.1 是一次**小型稳定性迭代**，不改界面、不加新功能，只把"派兵循环"里几个会把队伍空转或卡住的地方收掉。

### 1. 指令顺序不再被脚本改写

- 删掉"队伍站在目标点上就把攻城/攻占删成驻守/行军"的内部规则。
- 现在永远按你配置的顺序（例如 攻城 → 驻守 → 攻占 → 行军）找现场存在的那一条：
  - 敌方在建山道（菜单只有攻城/行军）→ 攻城
  - 我方在建（驻守/行军）→ 驻守
  - 地基/地皮（行军/驻守/扫荡）→ 按顺序落到可用的一条，扫荡不碰
- 站原地时不会再发出"行军到自己脚下"这种 0 秒空操作。

### 2. 没受理＝这条没成，按顺序换下一条

- 点完出征后当场复核队伍状态：
  - 还停在原地 → 换配置里的下一条指令继续试；
  - 已经行军/驻守/战斗/重伤 → 本轮停手，绝不补发第二条；
  - 读不到状态 → 保守停手，下一轮再看。
- 每一条未确认都会写清楚：页型 / 卡状态 / 角标 / 是"换下一条"还是"已忙起来"。

### 3. 每轮自检 + 看门狗，队伍不会闲死

- 每轮输出一行：`监控：main:1=驻守 main:2=停留 … → 可派未动作 0`。
- 可派却连续 2 轮没动作 → 解除该队冷却 + 告警，下一轮强制重试。
- 跨轮不记忆"失败过"，没有黑名单；唯一的暂停是"队伍忙"或"有待核对订单"，两者都由现场自动解除。
- 未确认后的冷却上限 60 秒，最多一分钟就重试。

### 4. 每轮 30 秒

默认检查间隔 45 秒 → **30 秒**；旧配置在界面上可以继续调。

### 5. 修复实机跑出来的崩溃

`出征未确认受理` 的收尾代码把截图（numpy 数组）当布尔值判断，实机会抛
`ValueError: The truth value of an array ... is ambiguous` 并停止 Worker。已修复并加了回归用例。

## 已知限制

- 读取成本未改：一支队伍一次定位约 38 秒，三队同一点仍逐队定位；本轮只动决策与失败处理。
- 铺路实战中的补给下降、遇敌路线重选、击退恢复仍未实现。
- 真实页面里"敌方正建山道 → 攻城"这条本次没有遇到（当时是我方状态），由单测覆盖，建议下次遇到时再看一眼日志。
- `--duration` 到点后要等当前轮巡检结束才退出（可能晚 1–3 分钟）。

## 安装

解压后运行 `app/SanmouAssistant.exe` 或 `启动助手.cmd`。发行包不含游戏、模拟器或账号数据。
