# 三谋助手 0.11.2

发布日期：2026-11-15

## 概述

0.11.2 是一版以自动铺路稳定性与头像角标识别为主的源码小版本，源于 2026-11-15 凌晨一次实机铺路卡死排查：铺路队回主城后不再出发、到点队伍每轮只报「铺路仍在进行或状态待确认」而路线段位不动。根因一是无角标队伍被左移布局窗里的头像装饰误判成「角标未识别」，二是角标掩罩越过黑色菱形底盘吃进头像背景，把真实「停留」图标在不同底色头像下的相似度拉到阈值以下。本版重写角标定位与状态判定、统一铺路游标推进，并补齐「不可派不再静默」「菜单未确认不得跳过」「重复到点不再重派」三处配套修复。刷武勋、讨贼、拉线与日常的既有执行逻辑未做改动。排查与干预留证见本机 `artifacts/analysis-2026-11-15-pave-stall/`（私有，不上传）。

## 主要变化

### 1. 铺路统一游标推进

- 路线进度 `idx` 永远指向下一个未处理点：队伍停在目标点（到点）或确认目标没有攻占指令（`PavePointUnavailable`）即连续前移，同一轮可跳过多个点，直至路线完成或需要等待现场。
- 启动恢复与正常运行共用同一套推进流程（`_advance_pave`）： settle 订单、写入 `idx`/状态、发布 `pave` 事件、清理重试计时一处完成，不再两处各写一份。
- 每轮每条路线最多成功派出一段：派出一单后即停手等下一轮，避免单轮连续派单把订单与现场观测搅在一起。

### 2. 铺路等待与防误跳

- 队伍已停下但坐标连续读不出时，暂停恢复本段并发布 `pave(waiting)` 事件（限频日志说明「已停下但坐标连续未读出」），不向旧目标重复派兵。
- 派出前若地块动作菜单未确认——既无「攻占」按钮、也没读到行军/调动/驻守/攻城/征兵/升级/扫荡等任何动作——不得按「无攻占」跳过：先留证（`pave-point-unconfirmed` 截图）并报错，下一轮重读现场再定，避免识别抖动把可达目标误跳。
- 现场不可派（无可派证据、重伤、体力为空/为零等）时不再静默 `continue`：按现场等待，发限频（10 分钟）可见日志与 `pave(waiting)` 事件，运行总览能看出该队为什么不动。

### 3. 重复到点重派修复

- 「队伍已停下，恢复当前未完成段」在派出前重新完整读取本队；重新读到已站在目标点（含上一帧快照刚错过到点、完整重读已到点）直接判定「已铺到、继续下一段」，不再机械重发同一目标段。
- 到点判定仍以完整重读为准，轻量快照只作线索；订单与进度原子落盘、结果未知不重发的规则不变。

### 4. 角标识别重写（删除多布局竞分）

- 不再逐套试 0/-12/-25 布局取匹配最强，也不再靠「任意位置有角标形状」猜测是否继续试布局；改为按本队血条独立二维位置测量（`hud_offset`）：水平在 -31..+6 内连续取值，纵向按行扫描取血条条带，测不到水平位置就不能正向确认空闲。
- 模板匹配只补偿血条测量后的小残差；掩罩半径 22→17（`MATCH_RADIUS`），只覆盖角标黑色菱形底盘内部，不再吃进头像亮肤色/发丝背景。同一「停留」图标：亮色头像下 0.828→0.946，深色头像下 0.931→0.992，其他状态串判分数仍在 0.5 以下。
- 模板只负责已知状态；认不出的亮字形保守保持「未识别」（unknown），绝不降级猜空闲或某种状态。

### 5. 空闲改为正向结论

- 空闲要求同时成立：有效队伍行、整帧 HUD 有效（全黑/花屏等无法确认 HUD 的画面一律 unknown）、本格无角标、与主城位置证据一致。
- 新增 `marker_with_home_evidence`：空闲/练兵只存在于主城，与城外位置矛盾时一律转「未识别」（标注「主城状态与位置矛盾」），不作为可派证据，防止把城外停留队误判成空闲而重复派出。

## 升级说明

- 本轮不改变配置格式，无需迁移；铺路路线进度沿用持久化 `idx`，直接替换程序目录即可，`data/` 中的账号、配置、会话与数据库保留不动。
- 建议升级前停止运行中的任务，并备份 `data/` 目录。
