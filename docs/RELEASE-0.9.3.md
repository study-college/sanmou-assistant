# 三谋助手 0.9.3

2026-11-10 · Windows x64 · 铺路首次真实实战小版本。

## 本版改动

- **坐标定位改为结果验证**：`Game.go_to` 不再回读坐标输入框文字。输入后直接点“前往”，
  以实际到达的目标地块坐标作为唯一放行条件；页面仍停在坐标地图或地块坐标不符时，
  有界重输一次，两次仍不对就停在该段、记录现场，**绝不盲点攻占**。删除
  `Vision.map_input_coordinates` 和旧的“输入未核对不放行”回归。
  - 原因：输入框回读是代理指标，和“目标地块坐标”重复；历史上它没有拦住过真实输错，
    却两次误拦正确输入（2026-10-26 背景透字、2026-11-10 新主题阈值读空）。前往只移动镜头，
    不派兵、不消耗资源，按结果校验更稳，也不再依赖输入框主题/字体/亮度。
- **补给提醒自动处理**：出征后出现“当前补给少于80，战斗伤害降低25%…是否确认出征？”
  提示时，自动勾选“今日登录不再提示”并点“确定”，确认后按角标变化继续。只在同时读到
  “补给”与确认按钮时处理，不改点其他弹窗；每次保存 `pave-supply-prompt` 截图并发出
  `supply_prompt` 事件。2026-11-10 实机验证一次；勾选后补给 53/46/40 未再弹同阶段提醒，
  补给降到 0 仍可正常出征。
- **无攻占点跳过**：铺路目标地块菜单没有“攻占”（常见于别人已铺到该点）时，该段记为跳过，
  下一轮继续下一个点；先重截一帧再判定，避免一次识别抖动误跳。
- **守军战斗不再当异常**：铺路攻占空地的守军战斗是正常过程，只等待结束自动衔接；日志改为
  INFO 并限频，撤退仍保留 WARN。战斗后重伤属于后续议题。
- **衔接提速**：等待期新增 `Game.scan_pave_team` 轻量快照，只读坐标、角标和重伤，不反复打开
  部队总览；本机铺路巡检 30→15 秒。实机到点→下一段提交约 38–47 秒。

本机实测账号（实例 0），一队从攻城大营出发，按 17 个坐标铺路。2026-11-10 15:14 第一段提交，
18:25 完成 12/17（(80,494) 已确认），订单全部 accepted、pending 0；期间：

- 补给 <80 提醒一次，脚本自动勾选并确认，随后继续；
- 一段到点附近出现“战斗”角标，等待后自动续段，没有重复派兵；
- 全部导航使用结果验证式定位，没有因为输入框读数卡住；
- 补给降到 0 后仍正常派出，与用户口径一致。

未完成部分：17 段尚未全部走完；“无攻占跳点”和“下一段起点≠上一段终点”尚无自然样本，
由单测覆盖。

## 兼容性与边界

- 补给提醒只处理“补给”+确认按钮这一种弹窗；其他奖励/活动/协助确认不在此路径。
- 铺路遇到无攻占点会跳过，不再反复重试同一点；被跳过点不补攻占。
- 出征页仍核对“攻占”标题、按钮、自动回城、队伍卡与提交后角标证据；结果不对不提交。
- 仍需分别验证其他账号、其他赛季布局、长期无人值守与不同网络环境。
